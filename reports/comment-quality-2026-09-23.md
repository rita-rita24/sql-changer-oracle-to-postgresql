# UIを増やさないコメント境界・引用文字列の品質改善

対象: `sql-changer-oracle-to-postgresql.html` / 2026-09-23

## GOODになったこと

- `nq'...'` の中に `NVL`・`DATE`・セミコロン・引用符があっても、中身を変換せず保持する。Unicodeの引用区切りも文字単位で読み取る。代替引用構文は従来どおり手動確認の対象。
- 関数引数・CAST・MERGEの行コメントを組み直すとき、終端の改行を保持する。生成したカンマ・閉じ括弧・CASE条件がコメントに巻き込まれる不具合を修正した。
- MERGEの列別名の前後にあるコメントを保持し、コメント中の単語を列別名と誤認しない。引用された空白を含む列別名も保持する。
- 通常コメントを含む単純なROWNUM上限を変換する。フィルター→件数制限→ソートの順序を保ち、取り除いた上限条件のコメントはLIMITの前に保持する。ヒント付き・OR・サブクエリ等は対応範囲を広げない。
- IME変換中は、キーイベント側に入力中フラグが付かない場合もTab／EscapeでSQLを書き換えない。
- 警告判定で同じSQLの字句範囲・マスクを再利用する。呼び出しをまたいでSQLを保存しない。
- プレビュー対象を別名HTMLへ切り替えた場合も、正式なHTMLのURLを開ける。

静的HTML・CSS・テーマ処理・固定文言は変更前と同一で、ボタンは4個のまま。単一HTML・オフライン動作・SQLを外部送信しない構成を維持した。

## 根拠と再現

引用記法の字句規則は[OracleのLiterals仕様](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/Literals.html)に基づく。Oracle 26ai Free 23.26.3とPostgreSQL 15.17で、元SQLと変換SQLの値・NULL・行数・型分類・更新後の結果を比較する。

追加した実DBケースは `tests/fixtures/comment-database-cases.mjs` の109件で、既定の検証集合に組み込んだ。初回の探索に含めたCRだけの改行43件は、Oracle自体が行コメントを終了せずエラーになったため有効SQLの集合から除外した。初回記録は `comment-discovery-before-2026-09-23.json` に残した。Oracleが拒否する引用符を含む別名の1件は、空白を含む有効な引用別名へ修正した。LFとCRLFは比較対象に含む。新しい許容差・例外は追加していない。

全体実行では、先行する更新テストが共有テーブルの走査順を変え、ROWNUM/LIMITの11例に差が出た。`comment-integration-before-2026-09-23.json` に記録を残し、4件の準備SQLで専用の表とデータを用意する構成に修正した。上限より前に順序を指定しないSQLについて、任意の実データで選ばれる行まで同一と保証するものではない。今回の比較は同条件で準備した専用データに対するもの。

```sh
SQL_CHANGER_DOCKER_CONTEXT=colima-sql-changer-validation npm run release
```

修正前後の実DB比較は `comment-database-before-2026-09-23.json` と `database-comparison-latest.json`、UI同一性と従来ケースの出力比較は `comment-ui-preservation-2026-09-23.json` に記録する。最終検査日時・ソースハッシュ・必須検査結果は [release-validation.json](release-validation.json) を参照する。現在は本体HTMLをそのまま利用・配布し、検証記録はこの `reports/` に集約している。

性能の参考測定は `comment-performance-2026-09-23.json`。端末で別の処理も動いており計測値のばらつきが大きいので、全入力での高速化率は主張しない。変換結果・警告の同一性と、重複走査の削減を確認した。

検証件数は任意のOracle SQLの成功率ではない。既存の型推定・NLS・互換関数・PL/SQL等の制約はREADMEとCONVERSION_POLICYに従う。
